# Advice contract

Every consult must stand alone. Include:

1. **Goal** — the outcome under review.
2. **Constraints** — boundaries and conventions that must remain true.
3. **State** — what was tried and what happened.
4. **Evidence** — relevant output, snippets, or exact file paths.
5. **Question** — one decision, not a general request for thoughts.

End with this instruction:

> Give a verdict, not a survey: "do X, not Y, because Z" plus the single risk
> that decides it. If the plan is sound, say so in one line. If missing
> information would change the answer, name it and explain what each answer
> would imply. Keep it under 200 words unless the architecture needs more.

The report must name the actual provider, model, authentication path,
disclosure state, exact context shared, read-only controls, process result,
session identifier when available, complete log path, full verdict, and any
fallback detected.

Advice is evidence, not authority. The main checks the verdict against the
actual diff, tests, and primary documentation. A contradictory finding gets
one focused reconciliation consult before the main decides.
